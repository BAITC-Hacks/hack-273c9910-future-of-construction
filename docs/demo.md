# Демонстрация на 3–5 минут

## Подготовка

Используйте Node.js 24. Из чистого клона выполните `npm ci`, затем `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run smoke`. Запустите `npm start`, откройте `http://localhost:3000`.

Начните новый сценарий и выключите городские события. Проверьте бюджет **100 условных единиц** и начальный Score **52.56**. Для демонстрации именно внешнего AI заранее настройте `.env.local`, перезапустите сервер и убедитесь, что источник анализа обозначен как LLM. При отсутствии ключа прямо называйте объяснение локальным.

## 1. Проблема и одинаковые условия — 30 секунд

«Мы сравниваем городские решения при ограниченном бюджете. Все команды получают одинаковые 100 единиц, районы и каталог. В данных десять показателей; чем больше, тем лучше. У Нуры два критических значения: школы 38 и медицина 35».

Покажите исходные районы. Уточните, что данные синтетические, как разрешено заданием.

## 2. Проверяемый план — 60 секунд

Выберите:

| Мера | Район | Цена |
|---|---|---:|
| M7 — Школа + детсад | Нура | 24 |
| M8 — Поликлиника | Нура | 20 |
| M10 — Освещение и камеры | Нура | 12 |
| M12 — Цифровая платформа обращений | Весь город | 14 |
| M5 — Чистое топливо | Сарыарка | 25 |

«Пять решений стоят 95, остаётся 5. Правила допускают две меры одного направления; выбирать по одной из всех пяти направлений не обязательно».

Завершите управление. Ожидается **Score 56.54**, **прирост около 3.99**, **0 критических показателей**. Покажите синергию M10 + M12 в Нуре.

«Школа даёт полный эффект +16, но с лагом 3 квартала за горизонт 8 кварталов реализуется +10: S1 меняется с 38 до 48. Числа считает движок; AI объясняет рассчитанный результат».

## 3. Изменение выбора меняет результат — 45 секунд

Пересоберите тот же набор, заменив только район M7: **Нура → Есиль**. Стоимость останется 95. Score должен измениться, а в Нуре останется один критический показатель — S1 = 38. Покажите, что объяснение сильных сторон и рисков также изменилось.

«Одинаковая стоимость не означает одинаковую пользу. Формула учитывает среднее по населению, слабейший район и штраф за критические значения».

## 4. Ограничения и рекомендации — 45 секунд

На новом плане покажите блокировку несовместимых M1 и M3, а также запрет третьей меры одного направления. Невалидный план нельзя завершить. Если нужен пример проверки бюджета, набор M3, M5, M7, M10, M13 стоит 119 и должен быть отклонён.

Откройте результат допустимого набора, покажите рассчитанные варианты замены и сравнение с оптимизатором. Скачайте Markdown-отчёт.

## 5. Дополнительный режим — до 45 секунд

При наличии времени включите городские события. После третьего решения появляется событие и резерв; доступный бюджет уменьшается. Покажите, что остаток, завершение плана и подбор альтернатив учитывают тот же лимит. Для соревнования сравнивайте только команды с одинаковыми условиями.

## На вопросы жюри

- **Откуда числа?** Из предоставленного датасета; все таблицы и формулы есть в [описании модели](model.md).
- **Что делает AI?** Сервер рассчитывает модель и передаёт LLM фактический результат для объяснения. При отказе сети работает явно обозначенный локальный анализ.
- **Можно подделать бюджет или Score запросом?** Эти поля не принимаются: сервер использует собственные данные и проверяет решения.
- **Как воспроизвести?** `npm ci`, проверки из README, контрольный набор на 95. HTTP smoke проверяет точный результат 56.54307.
- **Что добавила команда?** Интерактивный выбор, сравнение районов, алгоритм поиска лучшего набора, рекомендации замен, события, отчёт и интеграцию AI. Формула и датасет взяты из задания.
- **Что пока локальное?** История и таблица результатов хранятся в браузере; аккаунты и профили — в серверной SQLite.
